# Story spine: Automating the Wrong Layer

**Premise:** An FDE deploying AI has to ship a hypothesis about how the client should work, then make it possible for the client to revise that hypothesis.

**Basis:** Follows the [FDE treatment](every-handoff-is-a-claim.md), reframed at Tom's request on 2026-09-15. [How Durable Is the Target?](draft.md) remains the protected analytical alternative. [Sources](sources.md); [checkpoint](notes.md).

## Beats

### 1. A task has a target; a system requires organizational choices

- First-person advisory stance supplied by Tom; no invented client meeting or deployment result.
- A bounded extraction or classification task gives inputs and acceptance criteria. A campaign system requires decisions about briefs, agents, publication rights and exception capacity.
- The FDE must recommend something buildable while capabilities and useful boundaries change.

**Keep (draft):** “The system I ship contains a hypothesis about how the client should work.”

### 2. The current process offers a seductive specification

- Each box gets a copilot, each arrow an integration. Mapping reveals today's work; it does not justify tomorrow's architecture.
- Generic marketer: campaign production/reporting versus responsibility for audience growth within constraints. Different commitments imply different systems.

**Keep (draft):** “This is how yesterday's organization becomes tomorrow's software.”

### 3. Do / Know / Own makes the hidden choices explicit

- DO: reliable execution. KNOW: context and evidence. OWN: authority, responsibility and intervention.
- Better output, better context access and changed decision rights require different interventions. The client must authorize the last; a prompt cannot settle it.
- [Hammer](https://hbr.org/1990/07/reengineering-work-dont-automate-obliterate) supplies historical examples; [Gans](https://www.nber.org/papers/w35211) supplies a bundling mechanism. These support the practical design question.

### 4. Broader capability can support broader responsibility

- Proposed marketer: run bounded experiments and respond to results rather than commission every operation.
- [OpenAI](https://openai.com/index/how-ai-is-expanding-what-people-do-at-work/) documents task crossover in messages, not changed authority. Preserve that distinction.
- An owner may be a team; goal, act, observe, judge, adjust must return to someone able to change course.

### 5. Place the boundaries and implement governance

- [Baldwin](https://journals.sagepub.com/doi/10.1177/14761270251409566): dependencies and thin crossing points. [MIT CISR](https://cisr.mit.edu/publication/2026_0601_AIDecisionMatrix_SebastianWeillHaskampVomBrocke): decision rights.
- Illustrative video system: combine editorial decisions; delegate exports; preserve required independent authorization.
- Decide what the model interprets, software enforces, people authorize, and who may change policy. Calling it a compliance agent leaves those choices unanswered.

### 6. A working escalation feature can still fail operationally

- [Bainbridge](https://doi.org/10.1016/0005-1098(83)90046-8): lost practice and difficult residual exceptions.
- Who staffs the queue, sees the evidence and can intervene? Narrow scope or add support when ownership exceeds capacity.

**Keep (draft):** “Responsibility without control is just blame.”

### 7. Ship a hypothesis the client can revise

- Preserve evidence, intent, permissions, decisions and results across capability changes.
- Today's approval queue may later become exception handling. Keep its evidence usable when the handoff changes.
- First release tests output quality AND whether ownership, context transfer and exception capacity work. Retain payback and redesign tests in the [audit](target-durability-audit.md).

## Landing

**Keep (draft):** “We are deploying a way of working. We should be explicit about which parts of it are still a bet.”
