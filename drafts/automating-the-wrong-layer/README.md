# Automating the Wrong Layer

**What this is trying to say:** From the FDE's position, deploying an AI system means making a testable bet about how the client should work: which tasks belong together, where context and authority sit, and which human/AI handoffs will remain useful. Do / Know / Own helps make those choices explicit. The implementation should deliver value now while letting the client revise the division of work later.

## Treatments

- [How Durable Is the Target?](draft.md) is the more analytical treatment. It frames transformation as a rebundling hypothesis, uses O-ring tasks to model bottleneck migration and asks whether the target will survive through payback.
- [Automating the Wrong Layer: the FDE treatment](every-handoff-is-a-claim.md) is the current editorial direction. It situates the responsibility argument inside the practical work of advising a client and shipping a system. Do / Know / Own guides boundary choices; the ending asks what the first release will teach and whether the client can change the design afterward.

**Companion:** [The Target Durability Audit](target-durability-audit.md) is a facilitator-ready framework and chatbot prompt for applying the argument to a real CMO transformation decision.

**Status notes:** the FDE treatment follows Tom's request to write from the position of someone advising clients on AI deployment. It retains responsibility as the design starting point. The protected analytical manuscript remains available as an alternative focused on payback and bottleneck migration. The examples are generic design hypotheses; task-crossover evidence is not proof of expanded accountability. Identifying details from the originating project remain omitted.
